Quick navigator — design sketches

Decision: how a keyboard-only jump to a PR (and later a repo or an issue) lives in the githud island. Three theses, each built to shipping depth in the Color theme at 520pt. The typing is live in every option: click the field, type, use ↑ ↓ ⏎ esc. Where the field is pre-filled, that is the state's fixture; edit it freely.

AFilter the island

No new surface. ⌃⌥G summons the island as today; any printable key starts a jump line in the header slot, and the three lanes filter in place to what the island already knows. Nothing loads. esc clears the line first, then closes.

  • Matches on title, repo, #number, author, and branch (branch is fetched with the PR pulse, once).
  • A PR the island has not polled yet is the gap. The last row is always Search GitHub for “…”, one network call on ⏎.
  • Repos and issues arrive for free later: a repo row is any repo seen in the lanes; an issue is an Inbound row.

BPalette

A second surface on a second chord. ⌃⌥P raises a 520pt palette in the island's place: a well, then grouped results. Cached rows answer instantly; a GitHub search group fills in after 250ms of quiet. A focused row shows its chords.

  • Grammar by prefix: #214, owner/repo, is:issue label:bug, a branch name, a pasted URL.
  • ⏎ open · ⌘⏎ copy link · ⌘B copy branch · ⌘K copy gh pr checkout.
  • The HUD stays a HUD. The palette is where querying grows: repos, issues, actions.

CResolver

One handle in, one destination out. An agent hands you a branch name, a number, a repo, half a URL. ⌃⌥P raises a Connect-card-shaped ledger; you paste or type the handle and the three rows fill as it resolves: Handle → Repo → PR. No list to read.

  • Ambiguity is a stepper on the PR row, not a list: 1 of 2, ↑↓ to cycle.
  • A branch resolves through the cache first, then head: search on GitHub. The ledger shows which.
  • Repos and issues are the same shape: Handle → Repo → Issue. Free-text querying is not this thing.

Recommendation ratified 2026-09-04 · A · decisions in 2026-09-04-quick-navigator-agenda.md

A first, with C's handle parser inside it. The stated pain is “I have a branch name or a number, not a link.” The island already holds every PR you own, and fetching the head branch with the pulse makes that name searchable for zero new chrome and zero new hotkeys. Where A is thin, a PR not yet polled, borrow C's fallback rather than B's: when the typed text parses as a handle and the cache has nothing, the search row says Find #214 in repos you own and lands on the PR, not a search page. B is the right shape only if querying issues by label becomes a daily act; today it is the most chrome for the least-stated need.
