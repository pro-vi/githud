# Work plans

Append-only. **Each file is correct only about the day it was written**, and none of
them are updated afterwards — a plan here may describe a design that was later changed
or dropped. They are kept as a record of how a change was decided, not as a statement
of how githud works.

For how githud works now, read [`docs/TOPOLOGY.md`](../TOPOLOGY.md). It is the one
document kept current, and it holds the rules the interface is built from.

The `status:` field in a file's frontmatter refers to that plan's own lifecycle
(proposed / active / completed / historical), not to the state of the project.
