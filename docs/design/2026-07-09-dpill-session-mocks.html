What the refuters established — code-verified, before any taste enters

Five load-bearing facts the design must answer to

F1 · confirmed

The inbound pill tier is dead code for you

PillMorph.fingerprint checks the gauge branch (:99) before the inbound branch (:110), and the gauge exists whenever you have any live PR. You chronically hold ~7 — so the "5 waiting" tier built in 9012859 has never once rendered on your pill. It fires only at radar 0 ∧ zero live PRs ∧ queue > 0.
F2 · confirmed

Radar and inbound can double-count one PR

A fresh third-party PR on a watch-subscribed owned repo is classified inbound at 62 (SignalClassifier.swift:127-131) → it's in rows.count — AND the search sweep returns it → it's in inboundActive. The radar side clears on read; the inbound side persists until close. Only designs drawing both counts at once are bitten — and the pill has no set-diff data to dedupe them.
F3 · the upstream decision

The pill's stale clock does not cover the inbound lane

The stale prefix keys off freshness, computed only from the radar+pulse poll clocks; the sweep deliberately never feeds it (PollReducer.swift:184-186), and the adopt rule holds items through failed sweeps (InboundItem.swift:113-116). So any variant showing an inbound count chronically can draw "5 waiting" under fresh chrome while two of them already merged during a failed-sweep window. Close it (per-fact stale clock) or keep the elevated inbound count-free. No designer noticed; this ranks above the vocabulary choice.
F4 · confirmed

Shield ⊥ gauge — today's colors never co-render

The danger-red critical shield needs rows non-empty; the gauge's Primer badges need rows.isEmpty. Two status-color families are never co-visible on the shipped pill — and the PAID color-doctrine blind-read proof ("lone red security shield, zero yellow") rests on exactly that. Composition is the only family that breaks it.
F5 · build constraint

The ladder order lives in three files, unpinned

fingerprint(), size(for:), and bodyValue each independently encode gauge-before-inbound, and no test pins the order (the existing inbound test uses pulse:[], so it passes under both orders). Any reorder must land with a lockstep edit ×3 plus a new order-pinning test, or the drawn pill, its width, and its spoken value can silently disagree.
F0 · the shipped baseline, honestly

Today's pill is not the calm baseline it's assumed to be

With radar 0 it shows the green+red gauge badges all day (chronic standing color) and breathes 60↔88pt on every radar zero-crossing. Click through the mocks below with that baseline in mind — one variant reduces both below today; others multiply them.

The hybrid — assembled from the ratifier's objection + the refuters' own evidence

Ladder for the transient, composition for the standing pair

The objection to A: a ladder tier only works if it is self-clearing — radar earns the top slot because acting on it clears it, but the inbound queue is a standing fact you return to over days; put it on top and it walls off the live gauge for weeks. The resolution was hiding inside F2: the radar∩inbound overlap IS the arrival knock — a new PR at your door already fires the inbound radar reason (81df372), so the pill announces arrivals through the transient tier and the standing debt persists in the lane. So the queue never needed the top slot; it needs persistent subordinate presence beside the gauge. And composition is safe exactly there: inbound ⊥ pulse is proven disjoint (F2 bites only radar co-display), and the standing tier renders only when radar is empty — the shield still never co-renders with the badges (F4 intact). Ladder: loading > radar > standing tier (gauge ⊕ queue) > check.

The decisions — three, separable, in dependency order

Ratify in one line

Ratified · 2026-07-10 (rev. 3 — the config resolution)

The ratifier held both truths — "maybe when there's an inbound it should just supersede?" (aesthetics: ink over the green/red badges) and the earlier "it blocks the PRs underneath" (utility) — and ruled the tie-breaker: "allow config with actual visual preview… provide a default but user can switch it up." Outcome: PillStyle = queueLeads (default) / standingMarked / standingCounted, chosen in an island chooser card whose previews are the REAL CollapsedPillView fed live data (radar suppressed, captioned — never a fabricated specimen). D1 (per-fact stale clock) builds unconditionally. WP: docs/plans/2026-07-10-001-dpill-config-wp.md. The green/red discomfort is logged as the color-doctrine row's first dogfood flicker — island badges untouched, watched.

D1 · close the stale-clock gap (F3)

Per-fact stale clock: the pill's caution prefix covers the inbound-count state iff the sweep clock (lastInboundSuccessAt) is degraded; radar/gauge states keep the poll clock, exactly as today.

Runner: yes — required before any chronic inbound count; worth doing even without the reorder (the gap is latent in today's rare tier too). Alternative: keep the elevated inbound count-free (C's thesis), which makes D1 optional.

D2 · where does the queue live? (revised after ratifier feedback)

(a) standing pair — queue beside the gauge in one standing tier (the hybrid; runner pick). Arrivals knock via the radar inbound reason; the standing debt stays visible without walling off your PRs.
(b) reorder — inbound above gauge (ladder-strict as originally specced). Rejected by the ratifier: a standing, non-self-clearing fact on top walls off the live gauge for weeks.
(c) keep today's order untouched — the queue stays invisible on the pill (F1's dead tier stands).

Runner: (a).

D3 · the queue's strength in the standing tier

(i) marked — dim count-free tray beside the gauge (108pt chronic; F3 closure optional — the safest claim);
(ii) counted — full tray+count segment (123pt chronic; both numbers glanceable; requires D1);
(iii) pip / typed markers — the A2/C2-T1 add-ons remain available on top of any pick.

Runner: (i) to start — it answers "am I forgetting anyone?" all day with the smallest honest mark, dodges the stale-count risk entirely, and upgrading to (ii) later is additive (same tier, same grammar).

The recommended package, in full (rev. 2)

standing-marked = D2(a) standing pair + D3(i) count-free tray mark + tray.fill glyph family (+ tests updated) + queue-only standing state (tray+count at 60pt when all your PRs close — needs D1 only if you later take D3(ii); the queue-only count is rare, not chronic) + check weight regular (optional). No reorder → no F5 lockstep risk. D1 (per-fact stale clock) recommended on its own honesty merits, required only for chronic counts. Example one-liners: "runner picks" · "D2 a, D3 ii, D1 yes" · "hybrid marked, hold D1".

Killed for the record: composed-lanes, composed-reasons (F2 + F4 + misrepresented mechanics — the kills apply to composing RADAR into the strip; the standing pair composes only the proven-disjoint gauge⊕queue). Superseded: the D2 reorder (ladder-strict/A2/C2-T2 as originally ranked) — withdrawn on the ratifier's self-clearing objection.
